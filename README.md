# statico

> ⚠️ **Early alpha — not production-ready.** statico is built around how *I* work
> (polyglot codebases, AI-assisted development, fast iteration on plugins). Public
> tagging starts at `v0.1.0`; expect breaking changes between minor versions and
> rough edges. If you're looking for the most mature TypeScript dead-code tool,
> [knip](https://knip.dev/) is a better choice today. statico exists for people who
> want a single tool that spans TypeScript and Rust, treats AI assistants as
> first-class consumers, and lets them write project-specific rules without forking
> the analyzer.

[![Rust Edition 2024](https://img.shields.io/badge/rust-2024-orange.svg)](https://blog.rust-lang.org/2025/02/20/Rust-2024-edition.html)
[![License](https://img.shields.io/badge/license-MIT%2FApache--2.0-blue.svg)](#license)

statico is a static code analyzer for TypeScript and Rust projects. It detects
dead code, unused exports/types, circular dependencies, code duplication, and
framework-specific gotchas, computes a 0–100 health score, and ships outputs
designed for both humans and LLMs.

---

## What statico is good at

- **Polyglot projects.** Same tool for the TypeScript app and the Rust services
  next to it. No context switch, one report.
- **AI-assisted workflows.** `--format ai` (~500 tokens) and `--format context`
  (~100 tokens) plug straight into Claude / Cursor / Codex / agents that need
  a code-health snapshot. Project skills under `.claude/skills/` and
  `.pi/skills/` are generated by `statico setup`.
- **Customizable.** A JSON-RPC plugin system lets you write project-specific
  rules in TypeScript, Rust, Python, or any language with stdin/stdout. See
  [`examples/plugins/coverage-gap`](examples/plugins/coverage-gap) for a
  multi-hook plugin that demonstrates the protocol end-to-end.
- **CI-friendly.** SARIF for GitHub Code Scanning. Baseline files for
  ratcheting down issues over time. `statico fix` for safe automated cleanup.
- **No daemon, no server, no lock-in.** Single binary, JSON output, exit code
  on demand. Pipe it anywhere.

## What statico is **not** good at (today)

- **Speed at scale.** statico is not the fastest analyzer in this category. On
  large monorepos, expect knip and oxlint to run faster. statico optimizes for
  output flexibility and rule extensibility before raw throughput. The
  incremental cache helps a lot on warm runs (`~5–10×`); the cold run is the
  weak spot.
- **Stability guarantees.** Pre-1.0. Output schemas, plugin protocol, and CLI
  flags can change between releases. The baseline file format is versioned;
  other JSON shapes are not.
- **Coverage of every framework.** Built-in profiles cover Next.js, Angular,
  Vue, Svelte, Astro, Remix, NestJS, Payload CMS, and shadcn/ui — but
  detection is rule-based and incomplete. The right answer for niche
  frameworks is a plugin, not a built-in.
- **Replacing your linter.** statico is a project-level analyzer for things
  ESLint / clippy don't easily see (cross-file dead code, import cycles,
  duplication patterns). Run it alongside your linter, not instead of it.

## Detected issues

- **Dead code** — files unreachable from any entry point
- **Unused exports** — named exports never imported elsewhere
- **Unused types** — exported TypeScript interfaces/types never referenced
- **Unused dependencies** — packages in `package.json` never imported
- **Unlisted dependencies** — imports for packages missing from `package.json`
- **Circular dependencies** — import cycles between files
- **Duplicate code** — clone groups, mirrored directories, repetitive patterns
- **Framework gotchas** — error-prone patterns specific to your framework
- **Unresolved imports** — import specifiers that don't resolve to a real file
- **Plugin issues** — anything your custom rules surface

A 0–100 **health score** combines issue density and duplication. Tune it with
`--min-confidence` to filter out low-signal noise.

## Installation

### Cargo

```bash
cargo install statico
```

### npm (macOS / Linux × x86_64 / aarch64)

```bash
npm install -D @statico/cli
npx statico analyze .
```

### Prebuilt release

```bash
# Example: macOS arm64
curl -fsSL https://github.com/DonaldMurillo/statico/releases/latest/download/statico-macos-aarch64.tar.gz \
  | tar -xz
sudo install -m 0755 statico /usr/local/bin/statico
```

> **macOS quarantine note:** browser-downloaded tarballs are quarantined by
> Gatekeeper (unsigned binary). Clear it once with:
> ```bash
> xattr -d com.apple.quarantine /usr/local/bin/statico
> ```
> The `npx`, `cargo install`, and `curl | tar` paths above don't set the
> attribute, so they don't hit this dialog.

### GitHub Action

```yaml
- uses: DonaldMurillo/statico/.github/actions/statico@main
  with:
    format: sarif
    min-confidence: '0.5'
```

### From source

```bash
git clone https://github.com/DonaldMurillo/statico.git
cd statico
cargo install --path .
```

Prerequisites for source builds: [Rust](https://rustup.rs/) 1.91+ (Edition 2024).

## Quick start

Analyze the current project:

```bash
statico analyze .
```

When stdout is a terminal, the default output is human-readable Markdown. When
piped, it's enriched JSON.

Get an LLM-ready summary:

```bash
statico analyze . --format ai
```

Fail CI on new issues only (baseline-gated):

```bash
statico analyze . --update-baseline statico-baseline.json   # one-time
statico analyze . --baseline statico-baseline.json --exit-code
```

Apply safe automated fixes (unused exports + unused npm deps), with a dry-run
first:

```bash
statico fix .
statico fix . --apply
```

Watch mode:

```bash
statico analyze . --watch
```

Compare two snapshots:

```bash
statico analyze . --format json > before.json
# … make changes …
statico analyze . --format json > after.json
statico diff before.json after.json --format markdown
```

Interactive TUI:

```bash
statico tui .
```

## CLI reference

```
statico [OPTIONS] <COMMAND>

Commands:
  analyze      Analyze a project for code-quality issues
  fix          Apply safe automated fixes (unused exports + unused deps)
  diff         Compare two analysis outputs
  tui          Interactive terminal dashboard
  plugin       Manage plugins (init / build / run / list / doctor / schema / docs)
  setup        Generate AI-assistant skills (.claude / .pi / .cursor)
  init         Set up shell alias and completions
  doctor       Diagnose installation issues
  update       Self-update to latest release
  completions  Print shell completion script

Global options:
  --quiet      Suppress progress output
```

### `statico analyze`

| Flag | Type | Default | Description |
|---|---|---|---|
| `--format` | string | tty: `markdown`, piped: `json` | `json` `sarif` `markdown` `html` `ai` `context` `mermaid` `pr-comment` `fix` |
| `--min-confidence` | float | `0.0` (analyze), `0.5` (tui) | Drop issues below this confidence (0.0–1.0) |
| `--exit-code` | flag | false | Exit 1 if any issues remain after baseline + confidence filtering |
| `--no-cache` | flag | false | Skip the incremental cache; force a full re-parse |
| `--baseline` | path | — | Suppress issues whose fingerprints are listed in this file |
| `--update-baseline` | path | — | Write current issues as a baseline file and exit |
| `--watch` | flag | false | Re-run on file changes (uses the cache) |

### `statico fix`

| Flag | Type | Default | Description |
|---|---|---|---|
| `--apply` | flag | false | Actually rewrite files (default is dry-run) |
| `--unused-exports` / `--no-unused-exports` | flag | on | Drop the `export` keyword from declarations whose export is unused |
| `--unused-deps` / `--no-unused-deps` | flag | on | Remove unused entries from `package.json` |

### `statico diff`

```
statico diff <BEFORE> <AFTER> [--format json|markdown]
```

Exits 1 if `after` introduces new issues.

### `statico tui`

```
statico tui <PATH> [--min-confidence 0.5]
```

## Output formats

| Format | Use for |
|---|---|
| `json` | Tooling integration, snapshots for `statico diff` |
| `sarif` | GitHub Code Scanning, Azure DevOps |
| `markdown` | PR comments, human reading (default on tty) |
| `html` | Self-contained interactive report (offline) |
| `ai` | LLM tool calls (~500 tokens, top 20 issues + per-file risk) |
| `context` | System-prompt / `AGENTS.md` injection (~100 tokens) |
| `pr-comment` | GitHub PR review comment, GFM with emoji |
| `mermaid` | Dependency graph (color-coded entry / dead / hotspots) |
| `fix` | Dry-run cleanup hints (`git show` lines for review) |

Full details in [`docs/output-formats.md`](docs/output-formats.md).

## Configuration

`.statico.toml` in the project root, all keys optional:

```toml
# Default output format (CLI --format wins)
format = "json"

# Filter low-signal issues (CLI --min-confidence wins)
min_confidence = 0.0

# Exit 1 on issues (CLI --exit-code wins)
exit_code = false

# Glob patterns to skip
exclude = ["node_modules", "dist", "build", "**/*.generated.ts"]

# Glob patterns that override exclude
include = ["src/**/*.ts", "src/**/*.tsx"]

# Skip files larger than this (bytes); capped at 50 MB internally
max_file_size = 1_000_000

# Worker threads (0 = auto-detect)
threads = 0

# Auto-discover plugins under .statico/plugins/
plugin_auto_discover = true

# Explicit plugin entries (merged with auto-discovery)
[[plugin]]
name = "my-rule"
path = "./tools/my-rule"
enabled = true
languages = ["typescript"]

[plugin.settings]
# Forwarded to the plugin's `init` call as plugin_settings
strict = true
```

Full schema in [`docs/configuration.md`](docs/configuration.md).

## Plugins

statico's plugin system lets you write project-specific rules in any language
that can read/write JSON over stdin/stdout. Plugins are spawned as subprocesses
and speak JSON-RPC 2.0.

```bash
# Scaffold (typescript / rust / python)
statico plugin init my-rule --lang typescript

# Build (Rust plugins only — TS/Python plugins don't compile)
statico plugin build --name my-rule

# Run against a single file
statico plugin run my-rule --file src/foo.ts

# Inspect what's discovered
statico plugin list
statico plugin doctor    # check Bun / cargo runtime readiness
```

Plugins are auto-discovered from `.statico/plugins/` in the project root.
Each plugin can hook into:

- `analyze_file` — per-file analysis (add or override built-in)
- `discover_entries` — replace built-in entry-point detection
- `resolve_import` — replace built-in import resolution
- `post_analysis` — add cross-cutting issues after the full pass
- `format_output` — replace the built-in formatter for a given format

For a working multi-hook example, see
[`examples/plugins/coverage-gap`](examples/plugins/coverage-gap) — it uses
`analyze_file` to collect exports + tested names per file, then
`post_analysis` to flag exports without test references, and reads
configuration from the plugin's `settings` block.

Full protocol reference: [`docs/plugins.md`](docs/plugins.md).

## Framework profiles

| Framework | Detection | Entry Points | Gotcha Rules |
|---|---|---|---|
| **Next.js** | `next.config.*` | `page.tsx` `layout.tsx` `route.ts` `loading.tsx` `error.tsx` `not-found.tsx` | Conditional hooks, missing keys |
| **Angular** | `angular.json` | Components, directives, pipes, services, modules | — |
| **Vue** | `vue.config.*` / `nuxt.config.*` / Vite + Vue plugin | `.vue` SFCs | — |
| **Svelte** | `svelte.config.*` | `.svelte` components, `+page.svelte`, `+layout.svelte` | — |
| **Astro** | `astro.config.*` | `.astro` pages and layouts | — |
| **Remix** | `remix.config.*` | Route files in `app/routes/` | — |
| **NestJS** | `nest-cli.json` | Controllers, modules, services, guards, pipes | — |
| **Payload CMS** | `payload.config.*` | Collections, blocks, globals, fields | — |
| **shadcn/ui** | `components.json` | UI component files | — |
| **Generic** | always active | Test files, e2e specs, scripts | — |

Profiles can stack — a Next.js + Payload + shadcn project gets all three
profile sets active. Detection runs against marker files and
`package.json` dependencies, with workspace package directories included
in monorepos.

## AI integration

statico is designed to be readable by both humans and LLMs:

- **`--format ai`** — schema-versioned JSON, ~500 tokens, top-20 issues with
  ranked impact and `safe-to-delete` / `remove` / `investigate` suggestions.
- **`--format context`** — ~100-token plain text for `AGENTS.md` /
  `CLAUDE.md` / system-prompt injection.
- **`statico setup`** — generates skill files for Claude Code (`.claude/
  skills/`), pi (`.pi/skills/`), and Cursor (`.cursor/rules/`) so the
  assistant can call statico as a tool with no extra prompting.
- **MCP-friendly output** — both `ai` and `context` are stable enough to
  embed in MCP tool descriptions today.

## Status, stability, and where this is going

- **v0.1.0 = first public alpha tag.** Everything that worked on this
  branch's CI smoke tests works; nothing more is promised.
- **Output schemas may change.** The enriched JSON, AI JSON, baseline
  format, and SARIF emit are all versioned, but minor versions can shift
  field names until 1.0.
- **Plugin protocol may change.** Currently at the schema printed by
  `statico plugin schema --format json`. Pre-1.0.
- **Roadmap** is intentionally narrow: cycle-detection determinism,
  per-rule confidence tuning, language plugins (Python/Go via the same
  trait that's currently TS+Rust), `--fix` for more rules.
